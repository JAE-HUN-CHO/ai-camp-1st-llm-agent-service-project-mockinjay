# Domain — CareGuide

CareGuide is a **single bounded context**: a chronic kidney disease (CKD) patient assistant providing medical information, welfare-program guidance, dietary analysis, research-paper grounding, and learning quizzes through orchestrated LLM agents.

There is intentionally **one** ubiquitous language across the codebase and docs. Subsystems are technical concerns inside this single context, not separate contexts.

## Ubiquitous language (glossary)

| Term | Definition |
|---|---|
| **Patient** | The end user, assumed CKD stage 1–5. PII is treated as health data. |
| **Agent** | A Parlant-defined dialog actor. Exactly four exist: `Medical_Welfare`, `Nutrition`, `Research_Paper`, `Quiz`. |
| **Intent** | Output of the in-house intent classifier. One of 10 categories (MEDICAL_INFO, DIET_INFO, RESEARCH, …). |
| **Router** | `agent_manager.py`. Maps Intent → Agent ID. |
| **Confidence Score** | Float in [0,1] returned with each Agent answer. Below 0.7 → "전문의 상담을 권장합니다" suffix is appended (ADR-002). |
| **Emergency pre-filter** | Keyword check (흉통/호흡곤란/의식저하/경련) executed **before** intent classification; on hit, the LLM is bypassed and a 119 message is returned (ADR-002). |
| **Chat Room** | A persisted Parlant session; created up-front in MongoDB, then linked to a Parlant session id. |
| **Quiz** | RAG-grounded question set. Generated by `Quiz` agent; graded by the same agent with reference passages. |
| **NutriCoach** | The risk-scoring sub-feature of the Nutrition agent. Reads `user_health_records` to weight nutrient intake. |
| **Health Record** | A row in `user_health_records` (creatinine, gfr, optional fields). Editable by the patient. |
| **Point** | Internal currency. 100 P = 100 token. Earned via quiz/community/survey/attendance. |
| **Daily search counter** | TTL document in `daily_search_counter`; enforces KNO-006 (10/day research search). |
| **Clinical Trial** | A ClinicalTrials.gov record cached in `clinical_trials_cache`. Surfaced in UI per ADR-004. |
| **Vector index** | `pubmed_embeddings.vector_index`, 1536-d cosine, `text-embedding-3-small` (ADR-005). |

## Aggregates & invariants

### Patient
- Identified by `user_id` (string).
- Owns: `user_health_records`, `user_points`, `point_transactions`, `chat_rooms`.
- Invariant: a Patient may have **at most one** active emergency-mode dialog at a time (UI lock).

### Chat Room
- Identified by `room_id`.
- Owns: an ordered list of `messages` and a single `parlant_session_id`.
- Invariant: a Chat Room is created in MongoDB **before** the first Parlant call; `parlant_session_id` is linked synchronously (see recent commit `9398218`).

### Health Record
- Required: `creatinine` (float > 0), `gfr` (float > 0).
- Optional fields are nullable — the API **must** distinguish "not sent" (PATCH semantics, `model_dump(exclude_unset=True)`) from "explicitly cleared" (client sends `null`).

### Point Ledger
- `user_points.balance` MUST equal `sum(point_transactions.amount where user_id matches)`.
- All earn / spend / convert operations write **both** documents in a single logical transaction.
- Idempotency: every transaction carries a deterministic `source` + `metadata` key; duplicate inserts are rejected.

### Daily Search Counter
- Document id: `"{user_id}:{YYYY-MM-DD}"`.
- TTL index expires the document at the next local midnight.
- Increment is atomic (`$inc`).

## Key flows (high-level)

### 1. Chat turn

```
User → POST /api/chat/stream
  → Emergency pre-filter
      └─[hit]─► return 119 message, log
  → Intent classifier
  → Router: Intent → Agent ID
  → Parlant session.message(agent_id, room_id, text)
  → Agent answer + confidence_score
  → Confidence post-processor
      └─[<0.7]─► append "전문의 상담을 권장합니다"
  → Stream to client
  → Persist to messages collection
```

### 2. Research search (rate-limited)

```
User → POST /api/research/search
  → check daily_search_counter
      └─[≥10]─► attempt token deduction (user_points)
                  └─[insufficient]─► 402-style "프리미엄 안내" payload
                                     (NO real payment — ADR-006)
  → Research_Paper agent (vector_index)
  → return results, increment counter
```

### 3. Health record upsert

```
User → PUT /api/health-records/{id}
  → Pydantic model with optional null fields
  → record_update.model_dump(exclude_unset=True)
  → Mongo update_one with $set of returned dict only
```

## Cross-cutting policies

| Policy | Where enforced |
|---|---|
| Emergency keyword bypass | `backend/Agent/agent_manager.py` pre-filter |
| Confidence threshold (0.7) | post-process middleware |
| Daily search cap (10) | `backend/app/api/research_search.py` (or equivalent) |
| Point idempotency | DB unique index on `(user_id, source, metadata.<id>)` |
| PII redaction in logs | logging middleware in `backend/app/main.py` |
| No payment integration | global — ADR-006 is binding |

## What is **not** modeled here

- Multi-tenant / B2B context (single-tenant MVP).
- Insurance claim submission.
- Telemedicine video.
- Real payment / billing — ADR-006 keeps this out of MVP.
- Alternate frontends — `new_frontend/` is canonical (ADR-001); `frontend/` and `stitch_frontend/` are deprecated artifacts.
