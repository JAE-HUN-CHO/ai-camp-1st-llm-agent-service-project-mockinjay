# Domain — CareGuide

CareGuide is a **single bounded context**: a chronic kidney disease (CKD) patient assistant providing medical information, welfare-program guidance, dietary analysis, research-paper grounding, and learning quizzes through orchestrated LLM agents.

There is intentionally **one** ubiquitous language across the codebase and docs. Subsystems are technical concerns inside this single context, not separate contexts.

## Bounded context

```text
CareGuide (single context)
  ├── default chat: FastAPI → OllamaChatService → Mongo vector → Ollama
  ├── compatibility capabilities
  │     ├── Medical_Welfare / Research_Paper → Parlant
  │     └── Nutrition / Quiz / Trend_Visualization → local Agent
  └── local MongoDB: users, rooms/messages, health, rewards, cache, vectors
```

이 그림은 현재 실행 경로를 요약한다. 목표 feature/aggregate ownership은 Accepted ADR-013과
Phase 0 schema mapping에 따라 binding이다.

## Ubiquitous language (glossary)

| Term | Definition |
|---|---|
| **User Account** | An authenticated user with profile `general`, `patient`, or `researcher`. |
| **Patient** | The domain role of a user with `profile=patient`; not every authenticated user. PII is treated as health data. |
| **Agent** | A registered dialog capability. The current runtime exposes `Medical_Welfare`, `Nutrition`, `Research_Paper`, `Quiz`, and `Trend_Visualization`. |
| **Intent** | Output of the in-house intent classifier. One of 10 categories (MEDICAL_INFO, DIET_INFO, RESEARCH, …). |
| **Router** | `router/agent.py` classifies/synthesizes and `agent_manager.py` dispatches capabilities. The default Ollama chat path currently bypasses both. |
| **Intent Confidence** | Intent classification signal. It is not answer confidence or a medical-safety score. |
| **Answer Safety Assessment** | Planned typed safety result. No universal 0.7 answer threshold is currently implemented. |
| **Emergency pre-filter** | Single fail-closed policy enforced before routing/provider calls across current chat paths. |
| **Chat Room** | Mongo-persisted room. Parlant session linking is currently process-local/incomplete and is not yet a persisted invariant. |
| **Quiz** | RAG-grounded question set. Generated by `Quiz` agent; graded by the same agent with reference passages. |
| **NutriCoach** | The risk-scoring sub-feature of the Nutrition agent. Reads `user_health_records` to weight nutrient intake. |
| **Health Record** | A row in `user_health_records` (creatinine, gfr, optional fields). Editable by the patient. |
| **Point** | Internal currency earned by quiz/community flows. Token conversion is implemented in `backend/app/services/token_service.py`; the points ledger and token ledger are separate until a migration contract is accepted. |
| **Daily search counter** | Planned quota contract. No `/api/research/search` or `daily_search_counter` implementation is currently active; do not claim the 10/day cap is enforced. |
| **Clinical Trial** | A ClinicalTrials.gov record surfaced with source, faithful translation, and disclaimer in information-only mode per ADR-004. |
| **Vector index** | `pubmed_embeddings.vector_index`, 1536-d cosine (ADR-005), queried through the local Ollama embedding adapter. |

## Aggregates & invariants

### Aggregate ownership

`UserAccount`, `HealthProfile`, `HealthRecord`, `ChatRoom`, `PointLedger`, and
`DailySearchQuota` are separate aggregate roots connected by `user_id`. One does not own the others
internally. Cross-feature changes go through an application command or an explicit domain event.

### Chat Room

- Identified by `room_id`.
- Owns an ordered message history.
- Target invariant: Parlant-enabled rooms transition
  `CREATED → SESSION_PENDING → READY | SESSION_FAILED` and persist a
  `ParlantSessionLink(customer_id, session_id, capability)` before becoming READY.
- Current gap: room creation precedes Parlant creation, but the session link is not reliably persisted back to the room.

### Health Record

- Required: `creatinine` (float > 0), `gfr` (float > 0).
- Optional fields are nullable — the PUT API distinguishes "not sent" (`model_dump(exclude_unset=True)`) from "explicitly cleared" (client sends `null`).

### Point Ledger

- Target invariant: balance equals the sum of ledger transactions and commands are idempotent.
- Owner: `rewards`. Quiz and Community call its public commands instead of owning mutations.
- Existing collection differences require an additive migration decision before cleanup.

### Daily Search Counter

- Planned owner: `research`.
- Target document id is `"{user_id}:{YYYY-MM-DD}"` with atomic increment and expiry.
- Current gap: no active `daily_search_counter` implementation or index exists.

## Key flows (high-level)

### 1. Current default Chat turn

```text
User → POST /api/chat/stream
  → OllamaChatService
  → Mongo vector retrieval
  → Ollama generation
  → Stream to client
  → Persist to messages collection
```

`RouterAgent → AgentManager → five capability` is a compatibility fallback. A future
`SendChatMessage` that always routes intents is a behavior migration, not a description of current behavior.

### 2. Research search

```text
User → POST /api/trends/{temporal|geographic|compare|papers|mesh|summarize|translate}
  → Research/Trend provider and local vector adapter
  → return informational results
  → quota/point deduction is not currently wired to this route family
```

### 3. Health record upsert

```text
User → PUT /api/health-records/{id}
  → Pydantic model with optional null fields
  → record_update.model_dump(exclude_unset=True)
  → Mongo update_one with $set of returned dict only
```

## Cross-cutting policies

| Policy | Where enforced |
|---|---|
| Emergency keyword bypass | Single fail-closed EmergencySafetyPolicy before routing/provider calls |
| Answer confidence threshold | Not implemented; do not confuse router intent confidence with answer safety |
| Daily search cap | Not active; must not be advertised until a quota endpoint and test exist |
| Point idempotency | `rewards` owns PointLedger; additive schema migration remains future work |
| PII redaction in logs | Sensitive chat/health/token paths and verification artifacts are redacted |
| ClinicalTrials information-only | Binding in ADR-004 and enforced by the current contract |
| No payment integration | global — ADR-006 is binding |

## What is **not** modeled here

- Multi-tenant / B2B context (single-tenant MVP).
- Insurance claim submission.
- Telemedicine video.
- Real payment / billing — ADR-006 keeps this out of MVP.
- Alternate frontends — `frontend/` is the only product frontend (ADR-011); rollback copies under `logs/rollback/` are historical material.
