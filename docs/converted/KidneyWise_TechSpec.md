# 1. 프로젝트 개요

## 1.1 프로젝트명 및 부제

**프로젝트명:** KidneyWise (신장 지혜)

**부제:** 만성콩팥병(CKD) 환자와 바이오 연구자를 위한 RAG 기반 논문 분석 및 생명과학 지식 학습 플랫폼

## 1.2 프로젝트 비전

KidneyWise는 만성콩팥병(Chronic Kidney Disease, CKD) 분야에서 시작하여 의료 정보의 민주화를 실현하고자 합니다. 환자와 의료진 간의 지식 격차를 해소하고, 바이오 연구자들이 논문 분석에서 겪는 어려움을 해결하여, 모든 이해관계자가 최신 연구 동향을 쉽고 빠르게 이해할 수 있는 환경을 제공합니다.

## 1.3 핵심 가치 제안

**• 환자 중심:** 생명과학 배경지식이 없는 환자도 자신의 질병을 이해하고 치료 결정에 참여할 수 있도록 지원

**• 연구자 지원:** 약한 도메인 지식을 보완하고 논문 분석 시간을 획기적으로 단축

**• 지식 민주화:** 최신 신장병 연구를 쉽고 친절하게 설명하여 정보 접근성 향상

**• 근거 기반:** PubMed/PMC의 신뢰할 수 있는 논문을 기반으로 정확한 정보 제공

# 2. 배경 및 문제 정의

## 2.1 문제 상황 분석

### 2.1.1 환자 측면의 문제

① 지식 격차로 인한 의존성

만성콩팥병 환자들은 생명과학 배경지식이 없는 경우가 많아, 자신의 질병 상태, 치료 옵션, 부작용 등에 대해 충분히 이해하지 못한 채 의료진의 판단에만 의존하게 됩니다. 이는 치료 순응도 저하와 불안감 증가로 이어집니다.

② 정보 접근의 어려움

인터넷에는 신장병 관련 정보가 넘쳐나지만, 대부분이 검증되지 않았거나 환자가 이해하기 어려운 전문 용어로 가득합니다. 신뢰할 수 있는 최신 연구 결과에 접근하고 이해하는 것은 거의 불가능합니다.

③ 의료진과의 커뮤니케이션 장벽

제한된 진료 시간 안에 복잡한 의학 용어와 치료 계획을 이해하기 어렵고, 궁금한 점을 질문하거나 대안을 요청하는 것이 쉽지 않습니다.

### 2.1.2 의료진 측면의 문제

① 최신 연구 동향 파악의 어려움

신장병 분야에서는 매주 수십 편의 새로운 논문이 발표되지만, 바쁜 임상 일정 속에서 모든 최신 연구를 따라잡기는 불가능합니다. 특정 도메인에 대한 최신 지식 업데이트가 지연될 수 있습니다.

② 환자 교육의 시간 제약

제한된 진료 시간 내에 복잡한 의학 개념을 환자에게 쉽게 설명하는 것은 매우 어렵고 시간이 많이 소요됩니다.

### 2.1.3 바이오 연구자 측면의 문제

① 정보 과부하 (Information Overload)

PubMed에는 신장병 관련 논문만 해도 수만 편이 존재하며, 관련 논문을 찾고 읽는 데 과도한 시간이 소요됩니다. 연구자들은 자신의 연구와 직접 관련된 핵심 논문을 찾는 데만 수 시간에서 수 일을 소비합니다.

② 약한 도메인 지식 보완의 어려움

신장병 연구는 면역학, 대사학, 유전학, 약리학 등 다양한 분야가 융합되어 있습니다. 연구자가 모든 도메인에 전문가가 될 수는 없으며, 약한 분야의 논문을 이해하는 데 어려움을 겪습니다.

③ 컨텍스트 이해 부족

단순 키워드 검색으로는 논문 간의 의미 있는 연관성을 파악하기 어렵습니다. 예를 들어, 'podocyte injury'와 'glomerular damage'는 다른 용어이지만 밀접하게 관련된 개념입니다.

④ 연구 트렌드 파악의 어려움

분야별 연구 동향을 시각화하고 이해할 수 있는 도구가 부재하여, 어떤 주제가 주목받고 있는지, 어떤 연구 방향이 유망한지 판단하기 어렵습니다.

## 2.2 타겟 질병: 만성콩팥병 (CKD)

만성콩팥병을 첫 번째 타겟 질병으로 선정한 이유는 다음과 같습니다:

**• 높은 유병률:** 전 세계적으로 약 8억 5천만 명이 CKD를 앓고 있으며, 국내에서도 성인 7명 중 1명이 CKD 환자입니다.

**• 장기 관리 필요:** CKD는 만성 질환으로 평생 관리가 필요하며, 환자의 적극적인 참여가 예후에 큰 영향을 미칩니다.

**• 복잡한 치료:** 식이요법, 약물치료, 투석, 신장이식 등 다양한 치료 옵션이 존재하여 환자 교육이 매우 중요합니다.

**• 활발한 연구:** PubMed/PMC에 CKD 관련 논문이 풍부하게 존재하여 RAG 시스템 구축에 유리합니다.

## 2.3 해결 방안: KidneyWise 플랫폼

KidneyWise는 RAG(Retrieval-Augmented Generation) 기술과 도메인 특화 임베딩 모델을 활용하여 다음과 같은 솔루션을 제공합니다:

① 환자 맞춤형 설명

복잡한 의학 논문을 환자가 이해할 수 있는 쉬운 언어로 자동 변환하여 제공합니다. 전문 용어를 쉬운 용어로 바꾸고, 비유와 예시를 활용하여 설명합니다.

② 연구자 생산성 향상

의미 기반 검색으로 관련 논문을 빠르게 찾고, 논문 간 유사도 비교를 통해 연구 동향을 한눈에 파악할 수 있습니다. 약한 도메인의 배경지식을 쉽게 학습할 수 있는 요약과 설명을 제공합니다.

③ 신뢰성 있는 정보

PubMed/PMC의 검증된 논문만을 데이터 소스로 활용하며, 모든 응답에 출처를 명시하여 신뢰성을 확보합니다.

④ 시각화된 트렌드 분석

시간 흐름에 따른 연구 주제 변화, 주요 키워드 트렌드를 직관적인 차트로 제공하여 연구 방향 설정에 도움을 줍니다.

# 3. 기능적 요구사항 및 대응 방안

본 프로젝트는 RFP에 명시된 5가지 기능적 요구사항을 모두 충족하며, 각 요구사항에 대해 구체적인 구현 방안을 제시합니다.

## 3.1 [1순위 필수] 고급 PDF 처리

### 요구사항:

• PDF→텍스트 변환, 자동 청킹(문단/섹션별) 및 정제

• 논문 제목, 저자, 발행일, 키워드 등 메타데이터 구조화

### 구현 방안:

① PDF 파싱 및 텍스트 추출

**• 기술 스택:** PyPDF2, pdfplumber (레이아웃 보존), pymupdf (고속 처리)

**• 처리 방식:** 다층 파싱 전략으로 텍스트, 이미지(OCR), 테이블을 별도 추출

**• 품질 검증:** 추출 성공률 95% 이상 목표, 실패 시 원본 PDF 링크 제공

② 지능형 청킹 (Intelligent Chunking)

**• 섹션 기반 청킹:** Abstract, Introduction, Methods, Results, Discussion, Conclusion 등 논문 섹션을 자동 인식

**• 문단 기반 청킹:** 200-500 토큰 단위로 문맥을 유지하면서 분할 (Recursive Character Text Splitter 활용)

**• 오버랩:** 청크 간 50 토큰 오버랩으로 문맥 연속성 보장

**• 특수 처리:** Figure/Table 설명, 참고문헌은 별도 처리

③ 텍스트 정제 (Text Cleaning)

**• 노이즈 제거:** 헤더/푸터, 페이지 번호, 워터마크, 불필요한 공백 제거

**• 정규화:** 유니코드 정규화(NFKC), 줄바꿈 통일, 특수문자 처리

**• 생의학 용어 보정:** 약어 확장 (e.g., CKD → Chronic Kidney Disease), 유전자명 표준화

④ 메타데이터 구조화

정규표현식과 패턴 매칭을 활용하여 다음 메타데이터를 자동 추출:

**• 논문 정보:** PMID, PMCID, DOI, 제목, 초록

**• 저자 정보:** 저자명, 소속 기관, 교신 저자

**• 출판 정보:** 저널명, Impact Factor, 발행일, 출판사

**• 분류 정보:** MeSH Terms, 키워드, 논문 유형 (Review/Original Research/Case Study)

**• 통계 정보:** 피인용 수, 열람 수 (가능한 경우)

### 평가 기준 충족:

**✓** PDF→텍스트 변환 품질 95% 이상

**✓** 섹션별/문단별 자동 청킹 구현

**✓** 포괄적인 메타데이터 자동 추출 및 구조화

**✓** 한글/영어 논문 모두 지원

## 3.2 [2순위 필수] RAG 기반 LLM 응답

### 요구사항:

• 임베딩 모델로 청크별 벡터 추출 및 벡터DB 저장

• 검색된 논문 청크 + 사용자 쿼리 합성하여 LLM API 호출

• 신뢰성/근거 기반 핵심 답변 및 요약 자동 제공

### 구현 방안:

① 임베딩 생성

**• 도메인 특화 모델:** PubMedBERT (768 차원) 또는 BioBERT 활용

**• 처리 방식:** 각 청크를 독립적으로 임베딩하여 고차원 벡터로 변환

**• 성능 최적화:** 배치 처리(Batch Size: 32), GPU 가속 활용

**• 품질 검증:** 유사 논문들의 코사인 유사도 0.7 이상 확보

② 벡터 데이터베이스 구축

**• VectorDB 선택:** ChromaDB (로컬 개발/테스트용), Pinecone (프로덕션/스케일링용)

**• 인덱싱 전략:** HNSW(Hierarchical Navigable Small World) 알고리즘으로 근사 최근접 이웃 탐색 (ANN)

**• 메타데이터 필터링:** 발행일, 저널, 저자, MeSH Terms 등으로 필터링 가능

**• 성능 목표:** 1만 개 문서 기준 검색 시간 < 100ms

③ 쿼리-문헌 합성 프롬프트 설계

사용자 페르소나에 따른 맞춤형 프롬프트 템플릿:

**• 환자용 프롬프트:**

"당신은 만성콩팥병 환자를 위한 친절한 의료 정보 전문가입니다. 아래의 최신 연구 논문을 바탕으로, 중학생도 이해할 수 있는 쉬운 언어로 설명해주세요. 전문 용어는 일상적인 표현으로 바꾸고, 비유와 예시를 사용하세요. 각 정보의 출처를 명시하세요."

**• 연구자용 프롬프트:**

"당신은 신장병 연구 분야의 전문가입니다. 아래의 논문들을 분석하여, 연구자가 필요로 하는 핵심 정보(연구 방법론, 주요 발견, 한계점, 임상적 의의)를 구조화하여 제시하세요. 논문 간 차이점과 공통점을 비교하고, 연구 동향을 분석하세요."

프롬프트 구조:

1. 시스템 메시지: 페르소나 정의 및 응답 스타일 지정

2. 컨텍스트: 검색된 상위 5개 청크 (각 청크에 출처 메타데이터 포함)

3. 사용자 질문: 원본 쿼리

4. 제약 조건: "제공된 논문 정보만 사용할 것", "출처를 반드시 인용할 것", "확실하지 않으면 '논문에서 언급되지 않음'이라고 명시할 것"

④ LLM API 연동

**• 1차 LLM:** Claude 3.5 Sonnet (Anthropic API) - 긴 컨텍스트와 정확한 인용 능력

**• 2차 LLM (백업):** GPT-4 Turbo (OpenAI API) 또는 Gemini 1.5 Pro (Google API)

**• API 보안:** .env 파일로 API Key 관리, 환경 변수 사용, 하드코딩 금지

**• 요청 최적화:** 스트리밍 응답 (실시간 표시), 캐싱 (동일 쿼리 재사용), 토큰 제한 (max\_tokens: 1500)

⑤ 응답 후처리 및 근거 강조

**• 인용 하이라이팅:** 응답 텍스트에서 논문 청크의 원문이 사용된 부분을 자동 탐지하여 하이라이트 표시

**• 출처 링크:** 각 인용 옆에 [PMID: 12345678] 링크를 추가하여 PubMed 원본으로 이동 가능

**• 신뢰도 점수:** 응답의 각 부분에 대해 코사인 유사도 기반 신뢰도 점수 표시 (High/Medium/Low)

**• 경고 메시지:** 할루시네이션 가능성 경고, "의료진과 상담하세요" 안내 문구 자동 추가

### 평가 기준 충족:

**✓** 도메인 특화 임베딩 모델(PubMedBERT) 활용

**✓** 벡터DB 구축 및 효율적인 인덱싱(HNSW)

**✓** 페르소나별 맞춤형 프롬프트 설계

**✓** 근거 기반 응답 생성 및 출처 명시

**✓** 실시간 LLM 응답 및 하이라이팅 기능

## 3.3 [3순위 필수] 의미 기반 검색

### 요구사항:

• 임베딩 기반 쿼리 입력 → 의미 유사 논문 추천

• 논문 간 유사도 기준 비교, 관련 논문/키워드 추출 및 제안

### 구현 방안:

① 시맨틱 검색 (Semantic Search)

**• 검색 알고리즘:** 사용자 쿼리를 임베딩하여 벡터DB에서 코사인 유사도 기반 Top-K 검색 (K=10)

**• 하이브리드 검색:** 시맨틱 검색(70%) + BM25 키워드 검색(30%)을 결합하여 재현율 향상

**• 필터링:** 발행 연도, 저널 IF, 논문 유형 등으로 결과 필터링 가능

**• 개인화:** 사용자의 과거 검색 이력과 북마크를 반영한 재순위화 (Re-ranking)

② 유사 논문 추천

**• 논문 기반 추천:** 사용자가 선택한 논문과 유사한 논문 5-10개 추천

**• 다양성 확보:** Maximal Marginal Relevance (MMR) 알고리즘으로 유사하면서도 다양한 논문 추천

**• 설명 가능성:** 각 추천에 대해 '이 논문을 추천한 이유' (유사도 점수, 공통 키워드 등) 제시

**• 중복 제거:** 동일 저자의 동일 데이터 재분석 논문은 자동 제외

③ 논문 간 비교

**• 유사도 매트릭스:** 선택한 2-5개 논문 간의 코사인 유사도를 히트맵으로 시각화

**• 공통점/차이점 분석:** LLM을 활용하여 논문들의 연구 방법, 결론, 한계점 비교표 자동 생성

**• 인용 관계 분석:** 논문 간 인용 관계를 네트워크 그래프로 표시 (Cytoscape.js 활용)

④ 연관 키워드 제안

**• TF-IDF 추출:** 검색 결과 논문들에서 상위 20개 TF-IDF 키워드 추출

**• MeSH Terms:** 논문의 MeSH Terms를 집계하여 가장 빈번한 주제 제시

**• 키워드 확장:** 초기 쿼리에서 부족한 키워드를 추천하여 검색 개선 (예: 'kidney'만 검색 시 'renal', 'glomerular' 제안)

**• 워드 클라우드:** 키워드 빈도를 워드 클라우드로 시각화

### 평가 기준 충족:

**✓** 임베딩 기반 시맨틱 검색 구현

**✓** 하이브리드 검색으로 정확도 향상

**✓** 논문 간 유사도 비교 및 시각화

**✓** 관련 키워드 자동 추출 및 제안

**✓** 설명 가능한 추천 시스템

## 3.4 [4순위 필수] 연구 트렌드 분석

### 요구사항:

• 시간 흐름, 키워드, 연구 주제별 트렌드 시각화 지원

### 구현 방안:

① 시계열 트렌드 분석

**• 연도별 논문 수:** CKD 관련 논문의 연도별 출판 수를 라인 차트로 표시

**• 주제별 증감:** 특정 주제(예: 'stem cell therapy', 'SGLT2 inhibitor')의 연도별 언급 빈도 추적

**• 돌파구 탐지:** 급격한 논문 수 증가 시점을 자동 탐지하여 주요 이벤트(예: FDA 승인, 임상시험 결과) 표시

**• 시각화:** Plotly를 활용한 인터랙티브 타임라인 차트

② 키워드 트렌드

**• 핫 키워드 분석:** 최근 2년간 급부상한 키워드 Top 20 추출 (TF-IDF 변화율 기반)

**• 히트맵 시각화:** 연도(Y축) × 키워드(X축) 히트맵으로 트렌드 변화 표시

**• 키워드 라이프사이클:** 특정 키워드가 등장(Emerge) → 성장(Growth) → 성숙(Mature) → 쇠퇴(Decline)하는 패턴 분석

③ 연구 주제 클러스터링

**• 토픽 모델링:** LDA(Latent Dirichlet Allocation) 또는 BERTopic으로 주요 연구 주제 5-10개 자동 추출

**• 주제별 분포:** 각 주제가 전체 논문에서 차지하는 비중을 파이 차트로 표시

**• 주제 진화:** 5년 단위로 주요 주제가 어떻게 변화했는지 Sankey 다이어그램으로 표시

**• 시각화:** t-SNE 또는 UMAP으로 논문을 2D 공간에 투영하고, 주제별로 색상 구분

④ 연구자 네트워크 분석

**• 저자 협업 네트워크:** 공저자 관계를 노드(저자)와 엣지(공저 횟수)로 표현한 네트워크 그래프

**• 영향력 있는 저자:** PageRank 알고리즘으로 해당 분야에서 가장 영향력 있는 저자 Top 10 추출

**• 기관별 분석:** 주요 연구 기관의 논문 수와 피인용 수를 막대 차트로 비교

⑤ 대시보드 구성

**• 프레임워크:** Streamlit으로 인터랙티브 대시보드 구축

**• 레이아웃:** 상단에 필터(연도 범위, 저널, 키워드), 메인에 4개 차트(시계열, 키워드, 주제, 네트워크)

**• 인터랙션:** 차트 클릭 시 상세 논문 목록 표시, 드릴다운 가능

**• 내보내기:** 차트를 PNG/PDF로 저장, 데이터를 CSV로 다운로드

**✓** 키워드 기반 트렌드 분석

**✓** 연구 주제 클러스터링 및 진화 분석

# 4. 시스템 아키텍처

## 4.1 전체 아키텍처 개요

KidneyWise는 마이크로서비스 아키텍처 원칙을 따르며, 각 컴포넌트가 독립적으로 동작하고 확장 가능하도록 설계되었습니다.

### 주요 컴포넌트:

① 데이터 수집 레이어 (Data Collection Layer)

- PubMed/PMC API를 통한 논문 메타데이터 수집

- 논문 PDF 다운로드 및 저장

- Batch Processing 스케줄러 (주 1회 자동 수집)

② 전처리 레이어 (Preprocessing Layer)

- PDF 파싱 및 텍스트 추출

- 청킹 및 텍스트 정제

- 메타데이터 구조화

③ 임베딩 레이어 (Embedding Layer)

- PubMedBERT를 활용한 청크 벡터화

- 벡터 저장 및 인덱싱

④ 데이터 저장 레이어 (Data Storage Layer)

- PostgreSQL: 메타데이터, 사용자 정보, 히스토리 저장

- ChromaDB/Pinecone: 벡터 임베딩 저장 및 유사도 검색

- 파일 저장소: 원본 PDF 파일 저장

⑤ RAG 엔진 (RAG Engine)

- 쿼리 임베딩 및 유사도 검색

- 컨텍스트 합성 및 프롬프트 생성

- LLM API 호출 및 응답 생성

⑥ 분석 엔진 (Analytics Engine)

- 트렌드 분석 (시계열, 키워드, 토픽 모델링)

- 논문 네트워크 분석

- 시각화 데이터 생성

⑦ API 레이어 (API Layer)

- Django REST Framework 기반 RESTful API

- 인증/인가 (JWT 토큰)

- Rate Limiting 및 캐싱

⑧ 프론트엔드 레이어 (Frontend Layer)

- Streamlit: 빠른 프로토타입 및 대시보드

- HTML/CSS/JavaScript: 커스텀 UI 컴포넌트

## 4.2 데이터 흐름 (Data Flow)

① 초기 데이터 수집 및 구축

1. PubMed/PMC API → CKD 관련 논문 메타데이터 수집 (1만 건 목표)

2. 논문 PDF 다운로드 → 파일 저장소 저장

3. PDF 파싱 → 텍스트 추출 → 청킹 → 메타데이터 추출

4. 청크별 임베딩 생성 → 벡터DB 저장

5. 메타데이터 → PostgreSQL 저장

② 사용자 쿼리 처리

1. 사용자가 프론트엔드에서 질문 입력

2. API 서버가 질문 수신 및 전처리

3. 질문 임베딩 생성 → 벡터DB에서 유사 청크 검색 (Top-5)

4. 검색된 청크 + 메타데이터 → 컨텍스트 합성

5. 프롬프트 생성 → LLM API 호출 (Claude/GPT)

6. LLM 응답 → 후처리 (하이라이팅, 출처 링크 추가)

7. 프론트엔드로 응답 스트리밍 (SSE)

③ 트렌드 분석

1. 사용자가 트렌드 대시보드 요청

2. 분석 엔진이 PostgreSQL에서 메타데이터 조회

3. 시계열 분석, 키워드 추출, 토픽 모델링 실행

4. 시각화 데이터 생성 (JSON 형식)

5. 프론트엔드가 차트 라이브러리로 렌더링

④ 배치 업데이트

1. 스케줄러가 주 1회 트리거 (일요일 새벽 2시)

2. 최근 1주일 간 발행된 CKD 논문 메타데이터 수집

3. 새 논문 PDF 다운로드 → 전처리 → 임베딩 생성

4. 벡터DB 및 PostgreSQL에 추가

5. 에러 로그 기록 및 모니터링 알림

- email (VARCHAR): 이메일

- paper\_id (FK → papers)

- keyword\_id (FK → keywords)

## 7.2 벡터 데이터베이스 (ChromaDB/Pinecone)

### 컬렉션명: ckd\_papers

각 벡터 문서는 다음 정보를 포함:

- id (STRING): chunk\_id (PostgreSQL과 동일)

- embedding (VECTOR[768]): PubMedBERT 임베딩 벡터

- metadata (DICT):

• paper\_id: 논문 ID

• pmid: PubMed ID

• title: 논문 제목

• section: 섹션명

• publication\_date: 발행일

• journal: 저널명

• chunk\_text: 청크 원문 (검색 결과 표시용)

### 인덱싱 설정:

- 알고리즘: HNSW (Hierarchical Navigable Small World)

- M (연결 수): 16

- ef\_search (검색 시 탐색 깊이): 100

# 10. 결론 및 기대 효과

## 10.1 프로젝트 의의

KidneyWise는 단순한 논문 검색 도구를 넘어, 의료 정보의 민주화를 실현하는 플랫폼입니다. 만성콩팥병 환자들이 자신의 질병을 이해하고 치료 결정에 능동적으로 참여할 수 있도록 돕고, 바이오 연구자들이 논문 분석에 소요되는 시간을 획기적으로 단축하여 연구에 집중할 수 있도록 지원합니다.

본 프로젝트는 최신 RAG(Retrieval-Augmented Generation) 기술과 도메인 특화 임베딩 모델(PubMedBERT)을 활용하여, 신뢰할 수 있는 PubMed/PMC 논문을 기반으로 정확하고 근거 있는 정보를 제공합니다. 또한 모든 응답에 출처를 명시하고 할루시네이션을 최소화하여 의료 정보의 신뢰성을 최우선으로 합니다.

## 10.2 기대 효과

① 환자 관점

• 자신의 질병과 치료 옵션에 대한 이해도 향상

• 연구 동향 및 트렌드 한눈에 파악

• 유사 연구 발견으로 협업 기회 증대

③ 의료계 관점

• 근거 기반 의학(Evidence-Based Medicine) 실천 지원

④ 사회적 관점
